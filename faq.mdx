## Frequently Asked Questions

<AccordionGroup>
  <Accordion title="What is the Model Context Protocol (MCP)?">
    The **Model Context Protocol (MCP)** is an open standard created by Anthropic that standardizes how AI applications (such as Claude Desktop, Cursor, and custom autonomous agents) connect to external tools, databases, and APIs. Karada.ai automatically generates production-ready MCP-compliant servers directly from your existing OpenAPI and Swagger definitions with zero custom code.
  </Accordion>

  <Accordion title="What API specification formats are supported by Karada Auto-MCP?">
    Karada supports both **OpenAPI v3** (`.json` and `.yaml`) and **Swagger v2** (`.json` and `.yaml`) specifications. You can supply a live URL pointing to your API definition endpoint or upload raw specification files directly in the dashboard.
  </Accordion>

  <Accordion title="How does Karada differ from writing manual MCP servers with Python or TypeScript SDKs?">
    Writing manual MCP servers requires engineering teams to handwrite tool schemas, maintain proxy handlers, write custom parameter validation, and update code whenever API endpoints change. Karada's automated Go engine parses your existing OpenAPI specification, automatically derives tool names and parameter validations, dynamically injects runtime authentication headers, and provides 1-click cloud hosting and gateway multiplexing.
  </Accordion>

  <Accordion title="Do I need to know how to code to use Auto-MCP?">
    **No.** Karada parses your API specification and builds the entire MCP server automatically. Non-technical operators and product managers can supply an OpenAPI URL, verify the extracted tools, and deploy an active endpoint in under three minutes.
  </Accordion>

  <Accordion title="Can I use Karada with private or internal microservices behind a VPC?">
    **Yes.** When generating an Auto-MCP server, you can choose **Download as ZIP** to run the self-contained server binary inside your private VPC, local machine, or internal Docker swarm. Your production API traffic stays entirely within your private infrastructure.
  </Accordion>

  <Accordion title="How does Karada proxy authentication without leaking API keys to the AI model?">
    Karada parses the `securitySchemes` defined in your OpenAPI specification (such as Bearer tokens, API keys, and Basic auth). Secrets are stored in an encrypted vault (AES-256-GCM) and injected into outbound HTTP requests at the proxy edge. The AI client and LLM only receive the tool parameters—they never see your production API keys in their context window.
  </Accordion>

  <Accordion title="What is the Karada MCP Gateway?">
    The MCP Gateway is a unified multiplexer that combines multiple upstream MCP servers behind a single Streamable HTTP endpoint. Instead of adding 10 different server configurations to Claude Desktop or Cursor, you connect one Gateway URL that manages tool routing, prevents namespace collisions, and injects credentials.
  </Accordion>

  <Accordion title="Can I extend my MCP server with custom plugins?">
    **Yes.** The **Plugins Marketplace** provides modular extensions for telemetry, distributed request tracing, security headers, and rate limiting. You can also author and publish custom plugins using the standard Karada plugin manifest.
  </Accordion>
</AccordionGroup>

## Troubleshooting Guide

<AccordionGroup>
  <Accordion title="My MCP server will not connect to Claude Desktop">
    Review the following diagnostic checklist:
    1. Confirm the path in `claude_desktop_config.json` points to the exact **absolute path** of your server entrypoint.
    2. Confirm you ran `npm install` and `npm run build` in the downloaded project folder.
    3. Completely restart the Claude Desktop application to reload configuration files.
    4. Verify required environment variables (e.g. `API_KEY`) are properly declared in the `env` object.
  </Accordion>

  <Accordion title="The generated server throws 'Cannot find module' on startup">
    Run `npm install` within the unzipped server directory to ensure all dependencies and TypeScript build artifacts are correctly resolved.
  </Accordion>

  <Accordion title="OpenAPI specification returns a parsing error in Karada">
    Check that:
    - The URL returns raw JSON or YAML (not an HTML documentation splash page).
    - The URL is publicly reachable by Karada's validation parser.
    - All schema `$ref` pointers resolve correctly. Validate the spec using [editor.swagger.io](https://editor.swagger.io).
  </Accordion>

  <Accordion title="My deployment build is failing in the dashboard">
    Inspect the live **Deployment Logs** in your project's Deployments tab. Typical root causes include invalid specification URLs, unmapped required environment variables, or schema validation errors.
  </Accordion>
</AccordionGroup>
